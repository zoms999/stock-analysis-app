

제공해주신 DB 스키마와 기획서를 바탕으로 **"토너먼트(이벤트)" 기능의 UI/UX 및 로직 구현 가이드**를 제안합니다.

이미 `tournaments`와 `tournament_entries` 테이블이 잘 설계되어 있으므로, 이를 활용하여 **Type 1(코스피 소수점)**과 **Type 2(주가 예측)**를 아우르는 로직을 설계하겠습니다.

---

### 1. 토너먼트 로직 설계 (Logic & Flow)

#### 1.1. 토너먼트 생애주기 (Lifecycle)
1.  **UPCOMING (예정)**: 리스트에는 보이지만 참여 불가. 알림 신청 가능.
2.  **OPEN (참여 가능)**: 예측 값 제출 가능 (배팅).
    *   *패자부활/슬롯추가 로직 작동 구간*
3.  **LOCKED (마감/진행중)**: 참여 불가. 실제 시장 데이터가 생성되는 기간 (예: 월~금).
4.  **SETTLED (정산 완료)**: 실제 데이터와 예측값 비교, 우승자 선정, 상금/포인트 지급.

#### 1.2. 게임 타입별 데이터 저장 방식 (DB 활용)
제공된 `tournament_entries` 테이블의 `prediction_value`(단일 숫자)와 `prediction_json`(복합 데이터)을 활용합니다.

*   **Type 1: 코스피 소수점 뒤 2자리 맞추기 (로또형)**
    *   **저장 방식**: `prediction_value` 컬럼 사용 (예: `45` -> 0.45 의미).
    *   **승리 조건**: `ABS(실제값 - 예측값)`이 0인 유저. 다수일 경우 선착순 또는 N빵.
*   **Type 2: 삼성전자 주간 예측 (분석형)**
    *   **저장 방식**: `prediction_json` 컬럼 사용.
        ```json
        {
          "slots": [
             {"day": "Mon", "price": 72000},
             {"day": "Tue", "price": 73500},
             ...
          ],
          "accuracy_score": null // 정산 시 업데이트
        }
        ```
    *   **승리 조건**: (실제 가격과 예측 가격의 오차 합)이 가장 적은 순서대로 1~3위.

#### 1.3. 바이럴(패자부활/슬롯확장) 로직
기획서의 **"공유 시 슬롯 3개로 증가"**는 한 명의 유저가 한 토너먼트에 **여러 개의 답안**을 제출할 수 있다는 뜻입니다. 하지만 DB 스키마 상 `(tournament_id, user_id)`가 Unique로 잡혀 있으므로, **`prediction_json` 안에 배열 형태로 저장**하거나, **수정 기회를 부여**하는 방식으로 구현해야 합니다.

*   **구현 전략**: `prediction_json` 내부에 `entries` 배열을 둡니다.
    *   기본: 배열 길이 1 (답안 1개).
    *   SNS 공유 성공 시: `max_re_entry` 체크 후 배열 길이 3까지 허용.

### 2. UI/UX 구성 (Wireframes)

#### 2.1. 토너먼트 로비 (Lobby)
*   **카드 리스트 형태**: 진행 중인 토너먼트 노출.
*   **정보 표시**:
    *   타이틀: "제 12회 삼성전자 주가 예측 대회"
    *   상금: "총 1,000,000 포인트"
    *   남은 시간: "마감까지 02:15:33" (타이머)
    *   참여 현황: "현재 1,240명 참여 중"
*   **CTA 버튼**: [참여하기] / [결과보기]

#### 2.2. 상세 및 참여 화면 (Participation Page) - 핵심
화면을 좌/우 또는 상/하로 분할합니다.

*   **영역 A: 차트 및 정보 (Visual)**
    *   TradingView 위젯 등을 통해 해당 종목(예: 삼성전자)의 실시간/과거 차트를 보여줍니다.
    *   사용자가 차트를 보며 분석할 수 있도록 보조지표 도구 제공.
*   **영역 B: 예측 패널 (Interaction)**
    *   **입력 폼**:
        *   (Type 1) 숫자 입력기 (00~99).
        *   (Type 2) 월/화/수/목/금 날짜별 예상 종가 입력 필드.
    *   **슬롯(Slot) UI**:
        *   기본적으로 `Slot 1`만 활성화.
        *   `Slot 2`, `Slot 3`는 자물쇠(Lock) 아이콘으로 잠김.
        *   잠긴 슬롯 클릭 시 -> **"친구에게 공유하고 확률 3배 높이기!"** 팝업 호출.
    *   **제출 버튼**: [예측 제출하기] (포인트 차감 안내 포함).

#### 2.3. 바이럴 팝업 (Viral Modal)
*   **문구**: "아쉽게 빗나갈 것 같나요? 보험을 드세요!"
*   **기능**: 카카오톡/링크복사/트위터 공유 버튼.
*   **완료 후 UX**: 공유 완료 콜백을 받으면, 화면의 `Slot 2`, `Slot 3` 자물쇠가 풀리고 애니메이션과 함께 입력창이 활성화됨.

#### 2.4. 결과 및 리더보드 (Result)
*   **나의 결과**: 내 예측값 vs 실제값 비교 그래프.
*   **랭킹**: 1위~10위 유저 리스트 (닉네임, 적중률, 획득 상금).
*   **명예의 전당**: 과거 토너먼트 우승자 모아보기.

### 3. 기술 구현 가이드 (Implementation)

#### 3.1. DB 상호작용 (Supabase/SQL)

**A. 참여(Entry) 및 슬롯 확장 업데이트**
기존 스키마의 `prediction_json`을 활용하여 다중 슬롯을 저장합니다.

```sql
-- 예시: 유저가 SNS 공유 후 슬롯을 확장하여 데이터를 업데이트할 때
UPDATE public.tournament_entries
SET 
    re_entry_count = re_entry_count + 1,
    prediction_json = '{
        "slots": [
            {"val": 71000}, -- Slot 1 (기본)
            {"val": 72500}, -- Slot 2 (추가됨)
            {"val": 69000}  -- Slot 3 (추가됨)
        ]
    }'::jsonb
WHERE 
    tournament_id = '토너먼트ID' 
    AND user_id = '유저ID'
    AND re_entry_count < max_re_entry; -- 최대 횟수 제한
```

**B. 자동 정산 (Settlement Logic)**
이벤트가 종료되면 관리자(Admin) 혹은 스케줄러(Cron)가 실행할 쿼리 혹은 로직입니다. (PostgreSQL Function 예시)

```sql
-- Type 1: 코스피 소수점 정산 (예시)
-- 실제 정답이 45라고 가정
UPDATE public.tournament_entries
SET is_eliminated = CASE 
        WHEN prediction_value = 45 THEN false 
        ELSE true 
    END
WHERE tournament_id = '...';

-- Type 2: 오차 계산 (Logic은 서버 사이드에서 처리 권장, 복잡도 때문)
-- 서버에서 각 슬롯 별 오차 계산 후 가장 낮은 오차를 해당 유저의 최종 점수로 반영
```

#### 3.2. Frontend (Next.js) 흐름

1.  **공유하기 버튼 클릭**:
    *   Web Share API 또는 카카오 링크 API 호출.
    *   공유 성공 시, 백엔드 API `/api/tournament/unlock-slot` 호출.
2.  **슬롯 잠금 해제 API**:
    *   DB의 `tournament_entries` 테이블에서 `max_re_entry` 확인.
    *   아직 여유가 있다면 프론트엔드에 `success: true` 응답.
    *   UI에서 입력 폼 2, 3번 `disabled=false` 처리.
3.  **제출**:
    *   사용자가 입력한 값들을 배열로 묶어 DB에 `UPSERT` (Insert or Update).

#### 3.3. 관리자 페이지 기능
*   **토너먼트 생성**: `event_type` (DECIMAL, PREDICTION), `target_date`, `prize_pool` 설정.
*   **정답 입력**: 이벤트 종료 후 실제 코스피 지수나 주가 데이터를 입력 -> **[정산 실행]** 버튼 클릭 시 점수 계산 및 랭킹 산정 로직 트리거.

### 4. 시나리오 예시 (User Journey)

1.  **접속**: 유저 A가 '삼성전자 주가 예측' 토너먼트 클릭.
2.  **분석**: 차트를 보니 70,000원 근처에서 횡보 중.
3.  **1차 예측**: "금요일 종가 71,000원" 입력 (Slot 1).
4.  **불안감**: "아, 떨어질 수도 있겠는데?"
5.  **바이럴 유도**: 입력창 하단 "공유하고 슬롯 2개 더 받기" 클릭 -> 친구에게 카톡 공유.
6.  **확장**: Slot 2, 3 활성화됨.
7.  **추가 예측**: Slot 2에 "69,000원", Slot 3에 "73,000원" 입력. (Hedge 전략)
8.  **제출**: 최종 제출 완료. 포인트 차감.
9.  **결과 확인**: 금요일 장 마감 후 알림 수신. Slot 2(69,000원)가 적중하여 상금 획득.

이 구조는 기존 DB 스키마를 수정하지 않고(혹은 최소화하여) 기획 의도인 **바이럴 마케팅**과 **참여 유도**를 효과적으로 구현할 수 있는 방법입니다.
