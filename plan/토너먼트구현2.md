제 말이 맞습니다. 기획서상 **글로벌 서비스(다국어 지원, Stripe 결제)**를 지향하고 있으므로, 한국 내수용인 카카오톡 공유는 메인이 될 수 없습니다.

글로벌 투자/암호화폐 커뮤니티에서 가장 파급력이 큰 채널은 **X(구 트위터), 텔레그램, 디스코드**입니다. 이에 맞춰 공유 로직과 UI를 수정 제안합니다.

---

### 1. 글로벌 타겟 공유 채널 전략

글로벌 유저들이 투자 정보를 소비하는 채널 우선순위로 구성해야 합니다.

| 순위 | 채널 | 특징 | 비고 |
| :-- | :-- | :-- | :-- |
| **1** | **X (Twitter)** | 글로벌 금융/코인 트래픽의 핵심. 해시태그($BTC, #Tournament) 바이럴 효과 최상. | **필수** |
| **2** | **Telegram** | 투자 그룹, 시그널 방 등 커뮤니티 전파용. 링크 전달이 매우 활발함. | **필수** |
| **3** | **Copy Link** | 디스코드, 레딧(Reddit), 왓츠앱 등 자유로운 공유를 위한 링크 복사. | **필수** |
| 4 | Facebook | 동남아시아, 남미 등 특정 권역 타겟팅 시 유효. | 선택 |
| 5 | Kakao/Line | 한국/일본 접속 IP일 경우에만 노출하는 방식 고려. | 조건부 |

### 2. 수정된 UI/UX 가이드

#### 2.1. 공유 팝업 (Viral Modal) 디자인
"카카오톡 아이콘" 대신 글로벌 표준 아이콘을 사용합니다.

*   **타이틀**: "Share & Get 2 More Slots!" (공유하고 2개 슬롯 더 받으세요!)
*   **프리셋 메시지 (Pre-filled Text)**: 사용자가 공유 버튼을 누를 때 자동으로 완성될 문구입니다.
    *   *예시: "I predict Samsung Electronics closing at $55 this Friday! Join the tournament and beat me. 🚀 #Stock #Prediction"*
*   **버튼 구성**:
    *   [Icon] **Share on X** (검정 배경, 흰 로고)
    *   [Icon] **Share on Telegram** (파란 배경, 종이비행기 로고)
    *   [Icon] **Copy Link** (회색 배경, 체인 로고)

#### 2.2. Web Share API 활용 (모바일 대응)
모바일 브라우저(Chrome, Safari)에서는 OS 자체 공유 기능을 호출하는 것이 가장 자연스럽습니다.
*   **Mobile**: [Share] 버튼 클릭 시 -> 아이폰/안드로이드 하단 시트 호출 (문자, 왓츠앱, 인스타DM 등 유저가 자주 쓰는 앱 선택).
*   **PC**: 위에서 정의한 X, 텔레그램 버튼 직접 노출.

### 3. 기술 구현 (Intent URL & Logic)

글로벌 SNS는 SDK 설치 없이 **Intent URL(딥링크)** 방식이 표준입니다.

#### 3.1. Frontend 코드 예시 (Next.js)

```javascript
// 공유할 링크 (유저의 레퍼럴 코드가 포함된 링크 추천)
const shareUrl = `https://your-platform.com/tournament/${tournamentId}?ref=${userReferralCode}`;
const shareText = `Check out this tournament! I'm predicting the price of $${ticker}.`;

const handleShare = (platform) => {
  let url = '';

  switch (platform) {
    case 'twitter':
      // X(트위터) 공유 URL
      url = `https://twitter.com/intent/tweet?text=${encodeURIComponent(shareText)}&url=${encodeURIComponent(shareUrl)}`;
      break;
    
    case 'telegram':
      // 텔레그램 공유 URL
      url = `https://t.me/share/url?url=${encodeURIComponent(shareUrl)}&text=${encodeURIComponent(shareText)}`;
      break;
      
    case 'facebook':
      // 페이스북 공유 URL
      url = `https://www.facebook.com/sharer/sharer.php?u=${encodeURIComponent(shareUrl)}`;
      break;
      
    case 'copy':
       navigator.clipboard.writeText(shareUrl);
       alert('Link Copied!');
       // 복사는 즉시 서버에 공유 완료 신호를 보내기 애매하므로, 
       // UI적으로 "복사 완료" 후 [슬롯 해제 확인] 버튼을 활성화하는 UX 권장
       return;
  }

  // 1. 새 창으로 공유 팝업 띄우기
  if (url) window.open(url, '_blank', 'width=600,height=400');

  // 2. (중요) 공유 창을 띄운 것만으로도 '참여'로 인정해주는 것이 일반적인 UX (엄격한 검증 불가)
  unlockSlots(); 
};

// 슬롯 해제 요청 API 호출
const unlockSlots = async () => {
    const { data } = await supabase
        .from('tournament_entries')
        .update({ max_re_entry: 3 }) // 혹은 별도의 플래그
        .eq('tournament_id', tournamentId)
        .eq('user_id', userId);
        
    // UI 업데이트: 자물쇠 풀림 애니메이션
};
```

#### 3.2. "공유 했는지 어떻게 확인하나요?" (검증 로직 이슈)
Facebook, Twitter 등은 개인정보 보호 정책상 **"유저가 실제로 글을 게시했는지"** 여부를 API로 100% 리턴해주지 않습니다.

*   **현실적인 해결책 (Click-to-Reward)**:
    *   유저가 [Share on X] 버튼을 클릭하면 -> 공유 창이 뜸 -> **즉시 공유한 것으로 간주**하고 슬롯을 풀어줍니다.
    *   *이유*: 글 작성을 강제하려고 복잡한 OAuth(로그인 연동)를 붙이면 이탈률이 급증합니다. 버튼을 누른 유저의 80% 이상은 실제로 공유하거나, 적어도 홍보 의사가 있다고 판단하고 혜택을 주는 것이 서비스 활성화에 유리합니다.
    *   *보완책*: 만약 너무 어뷰징이 심하다면, **"추천인 링크를 통해 1명 이상 유입(클릭)되었을 때 슬롯 해제"** 방식으로 변경할 수 있습니다. (조금 더 난이도가 높음)

### 4. 정리

**글로벌향 토너먼트 공유 플로우:**

1.  **진입**: 유저가 토너먼트 예측 1개를 제출 (기본 슬롯 소진).
2.  **유도**: UI에 잠겨있는 Slot 2, 3와 함께 **"Unlock via X / Telegram"** 버튼 노출.
3.  **액션**:
    *   유저가 [X] 아이콘 클릭.
    *   브라우저 새 창으로 트위터 글쓰기 화면(`intent/tweet`)이 뜨고, 문구와 링크가 자동 입력됨.
4.  **보상**:
    *   우리 웹사이트는 버튼 클릭 이벤트를 감지하여 즉시 Slot 2, 3의 잠금을 해제(Unlock).
    *   유저에게 "추가 슬롯이 열렸습니다! 분산 투자를 통해 우승 확률을 높이세요." 토스트 메시지 출력.

이 방식이 기술적 구현 비용은 낮으면서 글로벌 유저들에게 가장 익숙한 UX입니다.
