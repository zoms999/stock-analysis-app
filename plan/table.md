제시해주신 기획서(v1.1)를 바탕으로 **Supabase(PostgreSQL)** 환경에서 바로 사용할 수 있는 데이터베이스 설계안(ERD 관점)을 제안합니다.

이 설계는 **회원 등급 관리, 구독 모델(SaaS), 포인트 시스템, 파트너 수익 쉐어, 토너먼트 로직**을 모두 포함하고 있습니다.

---

## 1. 데이터베이스 설계 개요

Supabase는 PostgreSQL을 기반으로 하므로 관계형 데이터베이스(RDBMS) 구조를 따르며, JSONB 타입을 활용해 차트 설정값 등 유연한 데이터 처리를 지원합니다.

### 주요 테이블 그룹
1.  **User & Auth**: 회원 정보, 프로필, 파트너 정보
2.  **Subscription & Payment**: 구독 플랜, 결제 내역
3.  **Community & Content**: 게시글, 차트 데이터, 조회 기록(일일 제한용)
4.  **Point & Wallet**: 포인트 내역, 입출금 신청
5.  **Tournament (Event)**: 대회 정보, 참가 및 예측 데이터

## 2. 테이블 상세 명세 (SQL Script)

아래 SQL을 Supabase의 **SQL Editor**에 붙여넣어 실행하면 기본 구조가 생성됩니다.

### 2.1. Enum (상태값 정의)
데이터 무결성을 위해 미리 타입을 정의합니다.
```sql
-- 포인트 트랜잭션 타입
CREATE TYPE point_type AS ENUM ('EARN', 'USE', 'WITHDRAW', 'ADMIN', 'REFUND');

-- 토너먼트 상태
CREATE TYPE tournament_status AS ENUM ('OPEN', 'ACTIVE', 'CLOSED', 'SETTLED');

-- 토너먼트 종류
CREATE TYPE tournament_type AS ENUM ('KOSPI_DECIMAL', 'STOCK_PREDICTION');
```

### 2.2. User & Partner (회원 및 파트너)
Supabase의 `auth.users`와 연동되는 `profiles` 테이블입니다.

```sql
CREATE TABLE public.profiles (
  id UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY, -- Supabase Auth ID 연결
  email TEXT NOT NULL,
  nickname TEXT UNIQUE,
  avatar_url TEXT,
  
  -- 레벨 및 권한
  user_level INT DEFAULT 1 CHECK (user_level BETWEEN 1 AND 10), -- 1~10등급
  is_partner BOOLEAN DEFAULT FALSE, -- 파트너 여부
  
  -- 추천인/마케팅
  referral_code TEXT UNIQUE, -- 본인의 추천 코드
  referred_by UUID REFERENCES public.profiles(id), -- 나를 추천한 사람 (파트너 수익쉐어용)
  
  -- 자산
  point_balance INT DEFAULT 0, -- 현재 보유 포인트
  
  -- 설정
  language_code VARCHAR(10) DEFAULT 'ko', -- 다국어 설정
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2.3. Subscription (구독 및 멤버십)
등급별 권한을 관리하는 테이블입니다.

```sql
-- 구독 플랜 정의 (관리자가 설정)
CREATE TABLE public.plans (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) NOT NULL, -- Free, Light, Standard, Premium, VIP
  price DECIMAL(10, 2) NOT NULL, -- 월 구독료
  target_level INT NOT NULL, -- 결제 시 부여될 등급 (예: Premium -> 8등급)
  
  -- 일일 제한 설정
  daily_view_limit INT DEFAULT 3, -- 하루 열람 가능 수 (무제한은 -1 또는 아주 큰 수)
  daily_write_limit INT DEFAULT 5, -- 하루 글쓰기 가능 수
  access_max_level INT DEFAULT 5, -- 열람 가능한 최대 게시글 레벨
  
  stripe_product_id TEXT -- Stripe 상품 ID 연동
);

-- 사용자 구독 현황
CREATE TABLE public.subscriptions (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES public.profiles(id) NOT NULL,
  plan_id INT REFERENCES public.plans(id),
  
  status VARCHAR(20) DEFAULT 'active', -- active, canceled, past_due
  stripe_subscription_id TEXT, -- Stripe 구독 ID
  
  current_period_start TIMESTAMPTZ,
  current_period_end TIMESTAMPTZ, -- 만료일
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2.4. Community & Chart (게시판 및 차트)
외부 API 데이터와 글쓰기가 결합된 영역입니다.

```sql
CREATE TABLE public.posts (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES public.profiles(id) NOT NULL,
  
  title TEXT NOT NULL,
  content TEXT, -- 텍스트 에디터 내용 (HTML/Markdown)
  
  -- 차트 데이터 (핵심)
  -- ticker: "BTC/USDT", "Samsung" 등
  -- chart_config: 차트 설정값, 드로잉 데이터 등을 JSON으로 저장하여 유연성 확보
  ticker_symbol VARCHAR(50),
  chart_config JSONB, 
  
  required_level INT DEFAULT 1, -- 이 글을 읽기 위해 필요한 등급
  view_count INT DEFAULT 0,
  
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 일일 활동 로그 (하루 열람/작성 제한 체크용)
CREATE TABLE public.activity_logs (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id UUID REFERENCES public.profiles(id) NOT NULL,
  type VARCHAR(20) CHECK (type IN ('VIEW', 'WRITE')), -- 글 보기/쓰기 구분
  target_post_id UUID REFERENCES public.posts(id), -- 어떤 글을 봤는지
  created_at TIMESTAMPTZ DEFAULT NOW()
);
-- 인덱스: 유저가 오늘 몇 개 했는지 빠르게 조회하기 위함
CREATE INDEX idx_activity_logs_user_date ON public.activity_logs (user_id, created_at);
```

### 2.5. Point & Reward (포인트 시스템)
포인트 적립, 차감, 환전 요청을 관리합니다.

```sql
CREATE TABLE public.point_transactions (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id UUID REFERENCES public.profiles(id) NOT NULL,
  
  amount INT NOT NULL, -- 양수(지급), 음수(차감)
  transaction_type point_type NOT NULL, -- ENUM: EARN, USE, WITHDRAW...
  description TEXT, -- "글 작성 보상", "글 열람 차감", "이벤트 참여" 등
  
  -- 관련 출처 (선택)
  related_post_id UUID REFERENCES public.posts(id),
  related_event_id UUID, -- 토너먼트 ID (아래 테이블 생성 후 연결)
  
  is_approved BOOLEAN DEFAULT TRUE, -- 관리자 승인 필요 시 False로 시작
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2.6. Tournament (토너먼트 & 바이럴)
이벤트 토너먼트 로직을 위한 테이블입니다.

```sql
CREATE TABLE public.tournaments (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT,
  
  event_type tournament_type NOT NULL, -- 코스피 맞추기 / 주가 예측
  target_date TIMESTAMPTZ NOT NULL, -- 예측 대상 날짜 (예: 다음주 금요일)
  
  status tournament_status DEFAULT 'OPEN',
  prize_pool TEXT, -- "1등: 아이패드" 등 텍스트 혹은 JSON
  
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE public.tournament_entries (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  tournament_id UUID REFERENCES public.tournaments(id) NOT NULL,
  user_id UUID REFERENCES public.profiles(id) NOT NULL,
  
  -- 예측 데이터
  prediction_value DECIMAL, -- 코스피 지수 예측값 등
  prediction_json JSONB, -- 삼성전자 월~금 예측 등 복잡한 데이터용
  
  -- 생존 및 부활 로직
  is_eliminated BOOLEAN DEFAULT FALSE, -- 탈락 여부
  re_entry_count INT DEFAULT 0, -- 부활(재참여) 횟수
  max_re_entry INT DEFAULT 3, -- 최대 부활 가능 횟수 (공유 시 증가)
  
  created_at TIMESTAMPTZ DEFAULT NOW(),
  
  UNIQUE(tournament_id, user_id) -- 중복 참여 방지 (부활은 update로 처리)
);
```

### 2.7. Partner Settlements (파트너 정산)
파트너 회원을 통한 매출 쉐어 내역입니다.

```sql
CREATE TABLE public.partner_settlements (
  id SERIAL PRIMARY KEY,
  partner_id UUID REFERENCES public.profiles(id) NOT NULL,
  
  source_user_id UUID REFERENCES public.profiles(id), -- 결제한 유저
  payment_amount DECIMAL(10, 2), -- 결제 금액
  commission_rate DECIMAL(5, 2), -- 커미션 비율 (예: 10.00%)
  settlement_amount DECIMAL(10, 2), -- 정산 받을 금액
  
  is_paid BOOLEAN DEFAULT FALSE, -- 정산 지급 완료 여부
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 3. 핵심 로직 구현 가이드 (Supabase 기능 활용)

### 3.1. 자동 회원가입 트리거 (Auth -> Profiles)
사용자가 소셜 로그인이나 이메일로 가입할 때 `profiles` 테이블에 자동으로 행을 생성해야 합니다.

```sql
-- 함수 정의
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profiles (id, email, nickname)
  VALUES (new.id, new.email, new.raw_user_meta_data->>'full_name');
  RETURN new;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

-- 트리거 연결
CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE PROCEDURE public.handle_new_user();
```

### 3.2. 일일 제한 체크 (Daily Limit Logic)
Next.js 백엔드(API Route)에서 글을 쓰거나 읽기 전에 아래 로직을 수행합니다.

1.  **유저의 플랜 조회**: `subscriptions` 테이블에서 유저의 현재 플랜(`daily_view_limit`) 확인.
2.  **오늘 사용량 조회**:
    ```sql
    SELECT count(*) 
    FROM activity_logs 
    WHERE user_id = '유저ID' 
      AND type = 'VIEW' 
      AND created_at >= CURRENT_DATE;
    ```
3.  **비교 및 처리**: 사용량이 한도보다 적으면 `activity_logs`에 INSERT하고 컨텐츠 반환, 아니면 에러(업그레이드 유도) 반환.

### 3.3. 포인트 차감 및 조회 로직
1.  **조회**: 포인트 잔액은 `profiles.point_balance` 컬럼에 저장하거나, `point_transactions`의 합계(`SUM`)로 계산할 수 있습니다. (성능을 위해 `profiles`에 캐싱해두고 트리거로 동기화하는 것을 추천)
2.  **차감**: 게시글 열람 시 `point_transactions`에 `{amount: -10, type: 'USE'}` 추가 -> Trigger가 `profiles.point_balance` 업데이트.

### 3.4. 바이럴/부활 로직 (패자부활)
1.  유저가 토너먼트에서 탈락(`is_eliminated = true`).
2.  프론트엔드에서 SNS 공유 완료 콜백 수신.
3.  API 호출 -> `tournament_entries` 테이블 업데이트:
    ```sql
    UPDATE tournament_entries 
    SET is_eliminated = false, 
        re_entry_count = re_entry_count + 1 
    WHERE user_id = '...' AND tournament_id = '...';
    ```
4.  동시에 포인트 차감 로직 수행.

## 4. 고려 사항

*   **RLS (Row Level Security)**: Supabase는 클라이언트에서 DB에 직접 접근할 수 있으므로 RLS 설정이 필수입니다.
    *   `posts`: `SELECT`는 등급 조건 충족 시 허용, `INSERT/UPDATE`는 본인만 허용.
    *   `profiles`: 본인 데이터만 수정 가능.
*   **실시간성**: 주식/코인 시세는 DB에 저장하지 않고 클라이언트(Front)에서 외부 API를 직접 호출하거나, 서버(Next.js)에서 캐싱하여 전달하는 것이 효율적입니다. DB에는 **차트의 설정값(어떤 지표를 켰는지, 드로잉 좌표 등)**만 저장합니다 (`chart_config`).
*   **글로벌 확장**: `profiles`의 `language_code`를 활용하여 프론트엔드에서 UI 언어를 전환하고, 게시글은 필요시 번역 API를 붙이거나 언어별 필터링을 제공해야 합니다.

이 설계안은 기획서의 모든 요구사항(등급, 포인트, 토너먼트, 파트너)을 수용할 수 있도록 정규화되어 있습니다.
