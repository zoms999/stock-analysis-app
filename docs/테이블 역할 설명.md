테이블 역할 설명
assets (자산 마스터 테이블)
역할: 거래 가능한 모든 종목(주식, 코인 등)의 기본 정보를 관리하는 기준 테이블입니다.
주요 컬럼: symbol (PK, 종목코드), asset_type (주식/코인 등).
관계: 다른 모든 테이블(market_prices, posts 등)이 이 테이블의 symbol을 참조합니다. 즉, 여기에 등록되지 않은 종목은 가격이나 예측을 저장할 수 없습니다.
market_prices (시장 가격 이력 테이블)
역할: 각 자산의 일별/시간별 가격 데이터를 저장합니다. 차트를 그리거나 과거 수익률을 계산하는 데 사용됩니다.
관계: ticker_symbol 컬럼이 assets 테이블의 symbol을 참조(Foreign Key)합니다.
daily_predictions (일일 예측 성과 테이블)
역할: 특정 post(예측 게시글)에서 예측한 날짜의 **목표가 대비 실제 결과(정확도)**를 저장합니다.
용도: "내가 예측한 가격이 오늘 실제로 얼마나 맞았는가?"를 계산하고 기록하여, 사용자의 적중률(랭킹)을 산정하는 근거가 됩니다.
관계: post_id를 통해 posts 테이블과 연결됩니다.
⚠️ 삭제 에러 원인 및 해결 방법
에러 메시지: ERROR: update or delete on table "assets" violates foreign key constraint "fk_prices_ticker" on table "market_prices"

원인: 사용자분께서 assets 테이블(부모)에서 종목(006400.KS)을 삭제하려고 시도하셨으나, market_prices 테이블(자식)에 해당 종목의 가격 데이터가 남아있어서 데이터 무결성 보호를 위해 삭제가 차단된 것입니다. (부모가 사라지면 자식 데이터가 고아가 되므로 DB가 막는 것입니다.)

해결 방법: 자식 데이터(market_prices)를 먼저 지우고 나서, 부모 데이터(assets)를 지워야 합니다.

아래 SQL을 순서대로 실행하시면 삭제됩니다:

sql
-- 1. 해당 종목의 가격 데이터를 먼저 삭제 (자식 삭제)
DELETE FROM public.market_prices 
WHERE ticker_symbol = '006400.KS';
-- 2. 그 다음 assets에서 종목 삭제 (부모 삭제)
DELETE FROM public.assets 
WHERE symbol = '006400.KS';
만약 posts나 다른 테이블에도 해당 종목을 참조하는 데이터가 있다면, 동일한 에러가 계속 발생할 수 있습니다. 그럴 경우 연관된 모든 데이터를 역순으로 지워야 합니다.
