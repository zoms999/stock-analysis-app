제공해주신 DB 스키마와 서비스 기획서를 바탕으로, **관리자(Admin) 페이지**에 필요한 핵심 기능과 메뉴 구조를 기획해 드립니다.

관리자 페이지는 **운영 효율성(회원/매출 관리)**과 **콘텐츠 관리(토너먼트/게시글)**에 초점을 맞추어 구성했습니다.

---

### [관리자 페이지 메뉴 구조 기획안]

#### 1. 대시보드 (Dashboard)
서비스의 현재 현황을 한눈에 파악하는 메인 화면입니다.
*   **주요 지표 (KPI)**:
    *   총 회원 수 / 신규 가입자 (금일)
    *   총 매출액 (Stripe 결제 기준) / 금일 매출
    *   현재 진행 중인 토너먼트 수
    *   정산 대기 중인 파트너 금액 (Settlement Pending)
*   **알림/할 일**:
    *   수동 포인트 지급 요청 건수 (처리 필요)
    *   파트너 정산 요청 건수
    *   신고된 게시글 건수

#### 2. 회원 및 구독 관리 (User & Subscription)
일반 회원과 구독 멤버십을 관리합니다.
*   **회원 목록 (`profiles`)**:
    *   회원 검색 (이메일, 닉네임, 추천코드)
    *   회원 상세 정보 조회 (가입일, 레벨, 포인트 잔액, 추천인)
    *   **기능**: 강제 탈퇴, 레벨 수정(1~10), 회원 차단(Ban).
*   **구독 현황 (`subscriptions`)**:
    *   유료 구독자 리스트 및 플랜 정보 조회.
    *   구독 상태 확인 (Active, Canceled, Past Due).
    *   **기능**: 구독 강제 해지, Stripe 결제 내역 링크.
*   **일일 사용량 모니터링 (`daily_usage`)**:
    *   특정 회원의 조회/작성 횟수 로그 확인 (어뷰징 탐지).

#### 3. 파트너 및 정산 관리 (Partner & Settlement)
인플루언서 마케팅 및 수익 쉐어 기능을 관리합니다.
*   **파트너 관리 (`profiles` where is_partner=true)**:
    *   파트너 권한 부여/해제.
    *   파트너별 추천 가입자 수 및 발생 매출 통계.
*   **정산 관리 (`partner_settlements`)**:
    *   정산 대기 목록 조회 (정산 금액, 커미션 비율).
    *   **기능**: `정산 완료(Paid)` 처리 (실제 송금 후 상태 변경).
    *   월별 정산 리포트 다운로드.

#### 4. 토너먼트 운영 (Tournament Ops)
이벤트 생성 및 결과 처리를 담당합니다.
*   **토너먼트 생성/수정 (`tournaments`)**:
    *   새 이벤트 등록 (제목, 설명, 이벤트 타입, 목표 날짜, 상금).
    *   이벤트 타입 선택 (코스피 맞추기 / 주가 예측 등).
*   **참가자 및 결과 관리 (`tournament_entries`)**:
    *   이벤트별 참가자 리스트 및 예측값 조회.
    *   **기능**: 우승자 선정 및 발표 (자동 정산 로직이 실패할 경우 수동 처리).
    *   이벤트 상태 변경 (OPEN → CLOSED → SETTLED).

#### 5. 게시판 및 콘텐츠 관리 (Content)
커뮤니티 건전성을 유지하고 공지사항을 관리합니다.
*   **게시글 관리 (`posts`)**:
    *   전체 게시글 조회 및 필터링 (최신순, 신고순).
    *   **기능**: 게시글 숨김/삭제 처리, 베스트 글 수동 지정.
    *   예측 정확도(`accuracy_score`) 재계산 트리거 (필요 시).
*   **공지사항 관리 (`notices`)**:
    *   공지사항 작성/수정/삭제.
    *   **기능**: 팝업 설정(`is_popup`), 상단 고정(`is_important`) 설정.

#### 6. 포인트 및 재무 (Finance & Point)
포인트의 흐름과 자산 데이터를 관리합니다.
*   **포인트 승인 관리 (`point_transactions`)**:
    *   `수동 지급` 요청 목록 조회.
    *   **기능**: 요청 `승인` 또는 `반려` 처리.
*   **포인트 내역 조회**:
    *   전체 포인트 적립/차감 로그 (이벤트, 패자부활, 글 열람 등).
*   **자산/종목 관리 (`assets`, `market_prices`)**:
    *   연동된 자산(Ticker) 목록 관리 (활성/비활성 처리).
    *   외부 API 연동 상태 모니터링.

#### 7. 시스템 설정 (Settings)
서비스의 기준값을 설정합니다.
*   **멤버십 플랜 설정 (`plans`)**:
    *   플랜별 가격, 일일 열람/작성 제한 횟수 수정.
    *   접근 가능 레벨 설정.
*   **관리자 계정 관리**:
    *   관리자 추가 및 권한 등급 설정.

---

### [개발 우선순위 제안]

1.  **회원 관리 & 공지사항**: 서비스 오픈 시 필수.
2.  **토너먼트 운영**: 핵심 바이럴 기능이므로 이벤트 생성/마감 기능 우선 구현.
3.  **포인트 승인 & 파트너 정산**: 수익 및 보상과 직결되므로 신뢰성 확보 필요.
4.  **대시보드 통계**: 초기에는 DB 직접 조회로 대체 가능하며, 추후 고도화.



관리자(Admin) 로그인을 위해 별도의 `admins` 테이블을 만들 필요는 없습니다.
현재 이미 존재하는 **`auth.users` (Supabase 인증)** 와 **`public.profiles` (프로필)** 테이블을 활용하는 것이 가장 효율적입니다.

핵심은 **"로그인 후, 이 사람의 레벨이 관리자 레벨(예: 10)인지 확인하는 것"**입니다.

다음은 구체적인 구현 단계입니다.

---

### 1. 관리자 권한 정의 (Database 설정)

기획서의 `user_level` (1~10)을 활용합니다. **레벨 10을 관리자(Admin)**로 정의합니다.

먼저, 관리자로 사용할 계정을 회원가입(또는 기존 계정) 시킨 후, DB에서 해당 계정의 레벨을 10으로 강제 변경합니다.

```sql
-- 예: admin@test.com 이라는 이메일로 가입한 유저를 관리자로 승격
UPDATE public.profiles
SET user_level = 10
WHERE email = 'admin@test.com';
```

### 2. 로그인 페이지 로직 (`/admin/login`)

관리자 로그인 페이지는 일반 로그인과 똑같은 Supabase Auth 기능을 사용하되, **로그인 성공 직후 레벨 체크 로직**이 추가됩니다.

**논리 흐름:**
1. 아이디/비번 입력 → `supabase.auth.signInWithPassword` 실행.
2. 로그인 성공 시 → `profiles` 테이블에서 해당 유저의 `user_level` 조회.
3. **분기 처리**:
    *   `user_level == 10`: `/admin/dashboard`로 이동.
    *   `user_level < 10`: "접근 권한이 없습니다." 에러 출력 후 강제 로그아웃.

**코드 예시 (Next.js/React 기준):**

```javascript
const handleAdminLogin = async (email, password) => {
  // 1. 기본 로그인 시도
  const { data: authData, error: authError } = await supabase.auth.signInWithPassword({
    email,
    password,
  });

  if (authError) {
    alert("로그인 실패: " + authError.message);
    return;
  }

  // 2. 프로필 레벨 확인 (보안 체크)
  const { data: profileData, error: profileError } = await supabase
    .from('profiles')
    .select('user_level')
    .eq('id', authData.user.id)
    .single();

  if (profileData.user_level === 10) {
    // 3. 관리자 확인됨 -> 대시보드로 이동
    router.push('/admin/dashboard');
  } else {
    // 4. 관리자가 아님 -> 쫓아내기
    await supabase.auth.signOut();
    alert("관리자 권한이 없는 계정입니다.");
  }
};
```

### 3. 미들웨어 보안 설정 (Middleware)

로그인 페이지를 통하지 않고 주소창에 `/admin/dashboard`를 바로 입력해서 들어오는 것을 막아야 합니다. Next.js의 Middleware를 사용하여 서버 사이드에서 차단합니다.

**Next.js Middleware 예시:**

```javascript
// middleware.ts
import { createMiddlewareClient } from '@supabase/auth-helpers-nextjs';
import { NextResponse } from 'next/server';

export async function middleware(req) {
  const res = NextResponse.next();
  const supabase = createMiddlewareClient({ req, res });
  const { data: { session } } = await supabase.auth.getSession();

  // /admin 경로로 접근하는 경우
  if (req.nextUrl.pathname.startsWith('/admin')) {
    
    // 1. 로그인이 안 되어 있으면 로그인 페이지로
    if (!session) {
      return NextResponse.redirect(new URL('/admin/login', req.url));
    }

    // 2. DB에서 유저 레벨 확인
    // (성능을 위해 여기서 DB 호출을 하거나, 로그인 시 쿠키에 admin flag를 심는 방식 사용)
    const { data: profile } = await supabase
      .from('profiles')
      .select('user_level')
      .eq('id', session.user.id)
      .single();

    // 3. 레벨이 10 미만이면 메인으로 튕겨냄
    if (!profile || profile.user_level < 10) {
      return NextResponse.redirect(new URL('/', req.url)); // 또는 403 페이지
    }
  }

  return res;
}
```

### 요약

1.  **계정 생성**: 일반 회원가입 절차로 관리자용 아이디를 만듭니다.
2.  **권한 부여**: DB 쿼리로 해당 아이디의 `user_level`을 `10`으로 수정합니다.
3.  **로그인 개발**: 로그인 성공 후 `user_level`이 10인지 확인하는 로직만 넣으면 됩니다.

이렇게 하면 별도의 관리자 테이블이나 복잡한 인증 구현 없이 기존 구조를 그대로 활용할 수 있습니다.


<header>

     <button onClick={() => router.push('/admin/dashboard')}>
       ⚙️ 관리자
     </button>
  )}
  
  <UserAvatar />
</header>
